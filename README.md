# Парсер эндуро-мотоциклов motocikl.by

Скрипт `parse_enduro_motocikl.py` скачивает первые 5 эндуро-мотоциклов из каталога motocikl.by и сохраняет результат в CSV-файл. Если в HTML есть ссылки на отдельные карточки — скрипт открывает их. Если сайт отдал товары прямо в каталоге без нормальных ссылок — скрипт забирает название, цену и характеристики прямо из HTML-блоков каталога.

## Запуск

```bash
python3 parse_enduro_motocikl.py
```

По умолчанию будет создан файл `enduro_motocikl.csv` в текущей папке. Его можно открыть в Excel, LibreOffice Calc или скачать с сервера как обычный CSV-файл.

## Настройки

```bash
python3 parse_enduro_motocikl.py \
  --url "https://motocikl.by/katalog/vse_tovary/mototsikly/enduro/" \
  --limit 5 \
  --output enduro_motocikl.csv
```

- `--url` — страница каталога.
- `--limit` — сколько первых мотоциклов парсить.
- `--output` — путь к CSV-файлу.
- `--pause` — пауза между запросами к страницам товаров, чтобы не перегружать сайт.
- `--debug-html catalog.html` — сохранить скачанную HTML-страницу каталога в файл. Можно указать имя файла самому; если написать просто `--debug-html`, скрипт сохранит HTML в `catalog.html`.

## Если появляется `No product links were found`

В новой версии скрипт сначала ищет ссылки на товары, а если ссылок нет — парсит сами HTML-блоки каталога с текстом вида `Мотоцикл ЭНДУРО`, `Бренд`, `Двигатель`, `Объем двигателя`.

Если ошибка всё равно появляется, сохраните HTML для проверки:

```bash
python3 parse_enduro_motocikl.py --limit 1 --debug-html catalog.html
```

После этого откройте или отправьте файл `catalog.html` разработчику. В этом файле будет именно та HTML-верстка, которую получил скрипт.

Если в `catalog.html` есть товары, но нет обычных ссылок на карточки, это нормально: скрипт теперь умеет делать CSV прямо из таких блоков каталога. Команда `python3 parse_enduro_motocikl.py --limit 1 --debug-html` тоже сработает: по умолчанию HTML сохранится в `catalog.html`.

## Важно про конфликт в Pull Request

Если в GitHub или в редакторе видны строки `<<<<<<<`, `=======`, `>>>>>>>`, значит это не Python-код, а незавершенный merge conflict. Такой файл запускаться не будет.

В файле `parse_enduro_motocikl.py` должна быть только одна копия скрипта:

- файл начинается с `#!/usr/bin/env python3`;
- файл заканчивается строками:

```python
if __name__ == "__main__":
    raise SystemExit(main())
```

- после этих строк не должно быть второй копии скрипта;
- в файле не должно быть строк `<<<<<<<`, `=======`, `>>>>>>>`.

Проверить это можно командами:

```bash
python3 -m py_compile parse_enduro_motocikl.py
rg '^(<<<<<<<|=======|>>>>>>>)|^#!/usr/bin/env python3' parse_enduro_motocikl.py
```

Команда `rg` должна показать только одну строку с `#!/usr/bin/env python3` и ни одной строки с `<<<<<<<`, `=======`, `>>>>>>>`.

## Как данные разбиваются по категориям

В CSV всегда есть базовые колонки:

- `Название`
- `Цена`
- `Ссылка`
- `Изображение`

Характеристики со страниц товаров добавляются отдельными колонками в формате:

```text
Категория: Характеристика
```

Например: `Двигатель: Объем`, `Размеры: Высота`, `Трансмиссия: КПП`. Если на странице товара нет явного заголовка категории, характеристика попадает в категорию `Характеристики`.
